# منصة الإحصائيات والمؤشرات السياحية

منظومة وطنية موحدة للبيانات والإحصاءات والمؤشرات السياحية في ليبيا، يكون فيها مركز المعلومات والتوثيق السياحي المصدر المركزي للبيانات المعتمدة، وتغذي لوحة القرار وVisit Libya وأطلس ليبيا والتقارير الحكومية من قاعدة بيانات واحدة.

> **حالة التشغيل الحالية:** المنصة مخصصة للاستخدام الداخلي في المركز عبر بيئة Manus الخاصة. لا ترفع أسرار OAuth أو مفاتيح PKI أو بيانات المستخدمين أو نسخة قاعدة البيانات الحية إلى GitHub.

## محتويات المشروع

| المسار                                    | الوظيفة                                                                |
| ----------------------------------------- | ---------------------------------------------------------------------- |
| `client/`                                 | تطبيق React وواجهات RTL والصفحات والمكوّنات.                           |
| `server/`                                 | خادم Express وواجهات tRPC ومنطق الصلاحيات والتقارير والتوقيع.          |
| `drizzle/schema.ts`                       | المخطط المرجعي لجداول MySQL/TiDB.                                      |
| `drizzle/*.sql`                           | ترحيلات قاعدة البيانات المولّدة والمراجعة.                             |
| `shared/`                                 | أنواع وثوابت ومنطق مشترك بين الواجهة والخادم.                          |
| `storage/`                                | مساعدو التخزين الكائني للملفات.                                        |
| `.github/workflows/ci.yml`                | فحص تلقائي عند كل Pull Request أو Push إلى `main`.                     |
| `.github/workflows/deploy.yml`            | مسار CD محمي للنشر بعد إعداد مزود الاستضافة وموافقة بيئة `production`. |
| `server/*.test.ts` و`client/**/*.test.ts` | اختبارات Vitest للخادم والواجهة والمنطق الحرج.                         |

## المتطلبات المحلية

يحتاج التشغيل المحلي إلى Node.js 22 أو أحدث، وpnpm 10، وقاعدة MySQL أو TiDB متاحة، وحساب OAuth تطويري متوافق مع Manus عند اختبار تسجيل الدخول. تحقق من الإصدارات:

```bash
node --version
pnpm --version
```

## تنزيل وتشغيل المشروع

```bash
git clone https://github.com/tidclibya2026/tourism-statistics-sdg.git
cd tourism-statistics-sdg
pnpm install --frozen-lockfile
```

أنشئ ملف `.env` محلياً. هذا الملف مستبعد من Git ولا يجب رفعه أو مشاركته:

```dotenv
DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DATABASE?ssl=true
JWT_SECRET=ضع_قيمة_عشوائية_طويلة_محلياً
VITE_APP_ID=معرف_تطبيق_OAuth_لبيئة_التطوير
OAUTH_SERVER_URL=https://api.manus.im
VITE_OAUTH_PORTAL_URL=https://oauth.manus.im
OWNER_OPEN_ID=معرف_مالك_بيئة_التطوير
OWNER_NAME=اسم_مالك_بيئة_التطوير
BUILT_IN_FORGE_API_URL=https://api.manus.im
BUILT_IN_FORGE_API_KEY=مفتاح_الخادم_لبيئة_التطوير
VITE_FRONTEND_FORGE_API_URL=https://api.manus.im
VITE_FRONTEND_FORGE_API_KEY=مفتاح_الواجهة_لبيئة_التطوير
TOURISM_DEPLOYMENT_ENV=development
```

لا تستخدم قيم الإنتاج على جهاز شخصي أو في Pull Request. إذا كانت بعض متغيرات OAuth أو Forge تدار تلقائياً من بيئة Manus، فاتبع قيم البيئة التي توفرها تلك المنصة بدلاً من اختراع قيم جديدة.

## تشغيل الواجهة والباك اند محلياً

يستخدم المشروع خادماً واحداً يقدّم API والواجهة أثناء التطوير؛ لذلك لا تحتاج عادةً إلى تشغيل خادمين منفصلين:

```bash
pnpm dev
```

بعد ظهور رسالة تشغيل الخادم افتح العنوان المحلي الذي يعرضه الطرفية، وغالباً يكون `http://localhost:3000`. تقوم Vite بتحميل الواجهة، بينما يقدّم Express مسارات OAuth وtRPC تحت `/api`. يعاد تحميل ملفات `client/` و`server/` تلقائياً عند تعديلها.

لبناء نسخة الإنتاج محلياً ثم تشغيلها:

```bash
pnpm check
pnpm test --run
pnpm build
pnpm start
```

لا تضع منفذاً ثابتاً داخل كود الخادم؛ بيئة التشغيل هي التي تحدد المنفذ عند النشر.

## فحوصات التشغيل والمراقبة

يوفر الخادم نقطتين منفصلتين لمنصة الاستضافة أو موازن الحمل:

- `GET /healthz`: يؤكد أن عملية Node.js تعمل، ولا يعتمد على قاعدة البيانات.
- `GET /readyz`: يعيد `200` عندما تنجح قراءة فحص قاعدة البيانات، أو `503` عند غيابها أو انتهاء المهلة.

اضبط `READINESS_TIMEOUT_MS` بين `250` و`10000` مللي ثانية. تضيف المنصة `X-Request-Id` لكل استجابة وتسجل المسار والحالة والمدة فقط؛ لا تسجل جسم الطلب أو cookies أو رؤوس المصادقة أو رابط قاعدة البيانات. استخدم `/healthz` لفحص الحياة و`/readyz` لقبول الحركة بعد اكتمال الاعتماديات.

عند استقبال `SIGTERM` أو `SIGINT` تتحول الجاهزية فوراً إلى `503`، ويتوقف الخادم عن قبول اتصالات جديدة وينتظر الطلبات الجارية حتى `SHUTDOWN_TIMEOUT_MS` قبل الإغلاق الإجباري. القيمة الافتراضية 10 ثوانٍ، ويجب أن تكون أقل من مهلة الإيقاف في منصة الاستضافة.

## تشغيل الحاويات

يبني `Dockerfile` التطبيق في مراحل منفصلة ويشغله بمستخدم غير جذر داخل صورة Node.js 22. ملفات `.env` والنسخ الاحتياطية والسجلات مستبعدة من سياق البناء. انسخ القالب المناسب إلى ملف غير متعقب ثم أدخل القيم عبر مخزن أسرار مؤسسي:

```bash
cp deploy/staging.env.template deploy/staging.env
docker compose --env-file deploy/staging.env -f compose.staging.yml up --build -d
```

في الإنتاج ابنِ الصورة المراجعة وادفعها إلى سجل خاص، ثم اضبط `APP_IMAGE` وشغّل `compose.production.yml`. لا تبنِ صورة الإنتاج وفي داخلها `DATABASE_URL` أو `JWT_SECRET` أو `AUTH_CLIENT_SECRET`؛ هذه القيم تمر عند التشغيل فقط. يجب وضع Reverse Proxy مع TLS أمام المنفذ المحلي، وأخذ نسخة قاعدة بيانات واختبار الاستعادة قبل أي ترحيل.

## قاعدة البيانات والترحيلات

يستخدم المشروع Drizzle ORM مع MySQL/TiDB. ملف `drizzle/schema.ts` هو المصدر البرمجي للمخطط، وملفات SQL في `drizzle/` هي سجل الترحيلات الذي يجب مراجعته قبل التطبيق.

لتوليد ترحيل بعد تعديل المخطط:

```bash
pnpm db:generate
```

اقرأ ملف SQL الجديد وتأكد من عدم وجود `DROP TABLE` أو حذف أعمدة غير مقصود. لتطبيق ترحيلات تمت مراجعتها على قاعدة التطوير:

```bash
pnpm db:migrate
```

وللاستخدام المحلي السريع فقط ينفذ الأمر التالي التوليد ثم التطبيق:

```bash
pnpm db:push
```

لا تستخدم `db:push` على قاعدة الإنتاج من جهاز مطور. في الإنتاج يجب اعتماد ملف SQL، أخذ نسخة احتياطية، ثم تطبيق الترحيل من خطوة نشر محمية ومراقبة.

## سير العمل التشغيلي للبيانات

يُعرّف المؤشر أولاً مع الوحدة والمنهجية والمصدر والإطار المرجعي. تدخل القياسات أو تستورد كمسودات، ثم يراجعها محلل مستقل، ثم يعتمدها مسؤول مخول. لا تعرض التقارير والخرائط والمساعد الذكي إلا القياسات المعتمدة وفق قواعد النظام. كل عملية اعتماد وتوقيع وتنزيل وثائق تسجل في سجل التدقيق المناسب.

## CI/CD عبر GitHub Actions

يوجد workflow في `.github/workflows/ci.yml` يعمل عند Push إلى `main`، وعند فتح أو تحديث Pull Request، ويمكن تشغيله يدوياً من تبويب Actions. ينفذ تثبيتاً مطابقاً لـ lockfile، وفحص TypeScript، والاختبارات، وتدقيق تبعيات الإنتاج، وبناء نسخة الإنتاج، ثم يحفظ `dist/` كـ artifact لمدة 14 يوماً. ويوجد `.github/workflows/deploy.yml` كمسار CD محمي؛ لا يعمل مع كل Push، بل عند tag بصيغة `v*` أو تشغيل يدوي، وبعد موافقة بيئة GitHub المسماة `production`.

لا يطبق workflow الحالي ترحيلات قاعدة البيانات ولا ينشر تلقائياً إلى بيئة حية. هذا مقصود لحماية البيانات ومنع تغيير المخطط دون موافقة بشرية. المسار الموصى به هو إنشاء فرع وPull Request، انتظار نجاح CI ومراجعة مستقلة، الدمج إلى `main`، النشر إلى staging، اختبار الصلاحيات والتقارير والتصدير، ثم تطبيق ترحيل الإنتاج بعد نسخة احتياطية وموافقة موثقة.

لإضافة نشر فعلي إلى مزود استضافة، يجب اختيار المزود أولاً وإنشاء Environment محمية باسم `production` من Settings → Environments، وإضافة Required reviewers، ثم حفظ `DEPLOY_WEBHOOK_URL` كـ Environment secret داخلها. يرسل `deploy.yml` رقم الالتزام والمرجع إلى webhook مزود الاستضافة فقط بعد الموافقة. لا تضع كلمات المرور أو مفاتيح SSH أو `DATABASE_URL` في YAML أو الكود. اجعل صلاحيات `GITHUB_TOKEN` أقل ما يمكن، وتأكد من أن webhook يقبل الطلبات الموقعة أو يطبق تحققاً خاصاً به قبل بدء النشر.

## ربط قاعدة البيانات الحية بالإنتاج بأمان

لا تربط قاعدة الإنتاج بعنوان محلي أو تستخدم بيانات اعتماد مشتركة بين التطوير والإنتاج. أنشئ قاعدة إنتاج منفصلة ومستخدماً خاصاً بالتطبيق بصلاحيات أقل ما يمكن، ومستخدماً منفصلاً للترحيلات إذا كان مزود القاعدة يدعم ذلك. فعّل TLS مع شهادة موثوقة، واستخدم شبكة داخلية أو قائمة سماح، وامنع الاتصالات العامة غير الضرورية.

خزّن `DATABASE_URL` في Secrets الخاصة ببيئة الإنتاج لدى منصة الاستضافة، وليس في GitHub repository variables العامة أو README. عند استخدام GitHub Actions لتطبيق ترحيل معتمد، خزّن السر في Environment محمية مثل `production-db`، فعّل Required reviewers، ولا تمنح Pull Requests من forks صلاحية قراءة السر.

| المرحلة         | الإجراء الإلزامي                                                          |
| --------------- | ------------------------------------------------------------------------- |
| الفصل           | قاعدة وOAuth وأسرار منفصلة عن التطوير والاختبار.                          |
| النسخ الاحتياطي | نسخة مشفرة ومختبرة الاستعادة قبل أي ترحيل.                                |
| الاتصال         | TLS، مستخدم محدود، شبكة مسموحة، وعدم تسجيل `DATABASE_URL`.                |
| المخطط          | مراجعة `drizzle/schema.ts` وملف SQL ومقارنة المخطط الفعلي.                |
| التطبيق         | تشغيل الترحيل من بيئة محمية وبموافقة بشرية؛ لا تستخدم `db:push` عشوائياً. |
| التحقق          | فحص الجداول وتسجيل الدخول والصلاحيات والقياسات والتقارير والتصدير.        |
| المراقبة        | سجلات أخطاء وتنبيهات دون طباعة الأسرار أو محتوى المستخدمين.               |
| الاستعادة       | إجراء مكتوب للرجوع إلى النسخة الاحتياطية عند فشل الترحيل.                 |

بعد الربط، ابدأ بترحيل غير مدمّر في نافذة اختبار. لا تُدخل بيانات تجريبية في قاعدة الإنتاج، ولا تخلط السجلات الرسمية بالبيانات التجريبية. ملفات SQL في GitHub تصف المخطط والتغييرات، وليست بديلاً عن النسخ الاحتياطية المشفرة لبيانات المركز.

## الأسرار والتوقيع الرقمي وPKI

يستخدم توقيع التقارير الحالي HMAC-SHA256 داخلياً للتحقق من سلامة التقرير داخل المنصة. إطار PKI الموجود في الكود لا يفعّل توقيعاً مؤسسياً قانونياً تلقائياً. لا تضع شهادة المؤسسة أو المفتاح الخاص في GitHub أو `.env` المرفوع؛ عند اعتماد التكامل مستقبلاً استخدم مخزن أسرار أو خدمة توقيع مؤسسية، ووثق سلسلة الشهادة وسياسة إبطالها، واختبرها على staging قبل المشاركة الخارجية.

## أمان GitHub

فعّل المصادقة متعددة العوامل لحسابات الإدارة، واجعل المستودع خاصاً، وقلل أعضاء الفريق إلى الحاجة التشغيلية. احمِ `main` بطلب Pull Request ونجاح CI ومراجعة مستقلة، وفعّل Dependabot أو مراجعة دورية للتبعيات دون تطبيق تحديث تلقائي على الإنتاج. راجع سجل Git قبل كل دمج للتأكد من عدم ظهور أسرار أو ملفات تصدير أو نسخ قواعد بيانات.

## النشر الحالي والانتقال المستقبلي

النسخة الحالية تعمل داخلياً على بيئة Manus الخاصة. عند الجاهزية للنشر الخارجي، أنشئ staging مستقلاً، واختر الاستضافة والدومين، ثم كوّن OAuth وTLS والنسخ الاحتياطي والمراقبة وسياسة الوصول، وأنجز اختبار قبول مؤسسي موثقاً قبل فتح أي وصول عام.

## الترخيص والملكية
